# 目录与动态网站

## 已有适配

`scripts/scrape_contacts.py` 自动识别：

- `bienaldolivrosp.com.br`：从公开页面解析展会编号、语言和目录设置，读取前端公开展商数据，按展商编号取字段；过滤其他展会的数据，不扫描产品描述。来源链接指向展商详情。
- `cbl.org.br` 路径含 `/nossos-associados`：只在 `.card-nossos-associados` 会员卡片内取值，遍历 `sf_paged` 分页。按名称、地址、网站形成公司标识，共用官网仍保留不同会员。

这些适配反映此前已验证的网站结构；页面改变时检查响应并修改当次任务副本，不将空解析视为成功。

```powershell
& $pythonExe -B -X utf8 (Join-Path $skillRoot 'scripts/scrape_contacts.py') 'https://cbl.org.br/en/nossos-associados/' -o './output/directories' --timeout 35

# 使用同一输出根目录恢复，刷新时才加 --refresh-directories。
& $pythonExe -B -X utf8 (Join-Path $skillRoot 'scripts/scrape_contacts.py') -i './directories.txt' -o './output/directories' --refresh-directories
```

`--directory-pages` 默认 200，独立于普通模式 20 页和 120 秒预算；`--directory-workers` 默认 3、最多 8；请求最多尝试 3 次。`--directory-pages 2` 可用于试跑，但达到限制会记录目录不完整并返回非零。不要用 `--max-pages` 声称已限制目录分页。

公开响应缓存在输出根目录 `directory_cache`，有效期 24 小时。每完成一页保存 CSV；恢复时仍使用同一输出根目录，最终结果会进入新的时间戳子目录。实际数据时间保留缓存原读取日期。重复页、空解析、数量不符、失败页或达到分页上限均不应报告目录完整。

公司电话只来自公司电话字段；有效巴西电话规范化到 +55，未知国家无区号电话保留原文而不猜测。地址不能拿会场地址代替。目录的 website 字段可能是社交主页，不能一律当作公司官网。专用模式不会自动访问每家官网补充；用户需要补充时另行处理已核实的官网并保留目录公司标识。

## 新目录与动态页面适配

先检查一个列表页及代表性的详情页，明确用户需要的是目录各公司还是站点运营方。目录采集不能直接运行整站邮箱正则后把结果当作所有公司数据。

1. 查明公开列表、详情页或前端公开读取接口，观察页面编号、游标、总数、每页数量及稳定公司编号。不要硬编码旧展会编号、抓取总数或临时请求凭据。
2. 有可直接读取的 HTML 或公开 JSON 时使用现有 HTTP 依赖；仅渲染后可见时使用当前可用浏览器或独立浏览器会话。普通爬虫没有通用浏览器回退，不能仅重跑同一 HTML 爬虫声称解决动态加载。
3. 把适配代码写到当次工作目录，复用 `contact_core` 与表格导出能力；公司字段在各自卡片/详情范围内提取。记录目录类型、公司标识、详情 URL、原电话、国家、抓取时间，缺失项留空。
4. 少量页验证多家公司不会串邮箱，邮编/门牌不会变成电话，主办方页脚不会成为展商数据；然后按用户范围完整分页。限制并发与请求速度，遵守站点公开访问规则；持续 403、验证码或登录要求时保留进度和原因，不反复重试规避访问限制。
5. 比较声明条数、唯一标识数、分页覆盖与重复页；列出未完成范围。若界面总数与实际列表不一致，分别报告，不能补造记录凑数。

目录补充官网时，保留目录行与官网结果的对应关系。共用官网、不同编号、同名异地、品牌与母公司都需按证据处理；无法确定的匹配另列，不静默合并。网站联系人图片或 PDF 不在现成脚本识别范围，需要按当前任务另行读取并标记出处。
